# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Lughati (لغتي) is a language-learning app for Arabic speakers: Expo SDK 57 + React Native 0.86 + TypeScript (`strict`), targeting Android first via **Expo Go** (no custom native code; iOS config exists but is untested and not released). Phase 1 foundation plus local, offline A1 and A2 lessons: no network, no real AI. The app has a unified brand design (see Theme), a static website in `site/` and Google Play release files in `docs/store/`. The README and TESTING.md are written in Arabic.

## Commands

```bash
npm install
npx expo start --lan            # scan the QR in Expo Go (same Wi-Fi), or enter exp://<LAN-IP>:8081
npm run typecheck               # tsc --noEmit (see the typed-routes caveat below)
npm run lint                    # expo lint (ESLint 9 flat config, eslint-config-expo)
npm test                        # jest (jest-expo preset); the full suite takes ~10 s locally (~2.5 min on a slow machine)
npx jest src/utils/routing.test.ts          # one file
npx jest -t "meets WCAG AA"                 # one test by name
npx expo-doctor                 # dependency/config check (the schema check needs network)
npx expo export --platform android          # proves the bundle builds
node scripts/render-icons.js                # icon/splash/favicon/Play graphic PNGs from assets/icon-src (needs Playwright + Chromium)
python3 scripts/build-site.py               # regenerates site/ (ar + en); the privacy text comes from docs/store/privacy-policy.md
```

Always add packages with `npx expo install <pkg>` (resolves SDK-compatible versions). Without access to Expo's API (cloud sandbox) it fails; then install the exact version listed in `node_modules/expo/bundledNativeModules.json`. Run typecheck + lint + tests before calling work done.

Expo SDK 57 postdates most model knowledge: before touching an Expo/RN API, check `https://docs.expo.dev/versions/v57.0.0/` (index: `https://docs.expo.dev/llms.txt`). Some doc pages (RTL, `Stack.Protected` `redirectTo`) describe "SDK 58+" behaviour that is not available on 57.

## Gotchas
- **Typed routes vs `tsc`.** `experiments.typedRoutes` is on. Once `expo start` has generated the git-ignored `.expo/types/router.d.ts`, template-string hrefs such as `router.push(`/lesson/${id}`)` fail typecheck; dynamic hrefs must be `{ pathname: '/lesson/[id]', params: { id } }` (home and learn already use it). Use the object form for new dynamic links.
- `@testing-library/react-native` is pinned to **13.3.3** and `react-test-renderer` to **19.2.3**: RNTL 14 needs React 19.3 while Expo pins 19.2.3.
- `tsconfig.json` sets `"types": ["jest"]` because TypeScript 6 no longer auto-loads `@types/*`.
- `jest.setup.ts` mocks AsyncStorage and the Ionicons font (async glyph loading causes `act()` noise).
- Jest runs in **`Asia/Riyadh` (UTC+3)**, set by `jest.global-setup.js` (setting `process.env.TZ` inside a test file has no effect). Calendar days come from `utils/day.ts` `dayOf` (local), never `toISOString().slice(0, 10)` (UTC).
- **No network in the cloud sandbox** for Expo's API/docs (`expo install`, `expo-doctor` schema check, docs.expo.dev fail); use `node_modules/expo/bundledNativeModules.json` for versions. `curl` to `*.vercel.app` is blocked too: use the Vercel MCP `web_fetch_vercel_url` to check the live site.
- Cairo fonts are imported per weight (`@expo-google-fonts/cairo/400Regular`, …) so the bundle does not carry every weight.

## Architecture

Routes live in `src/app/` (Expo Router; `@/*` → `src/*`) and stay thin; logic lives in `services/`, `store/`, `hooks/`, `utils/`.

**Navigation / auth guard.** `app/_layout.tsx` renders `null` (native splash held) until fonts (or a font error), persisted preferences, auth init and locale are all ready, then renders `navigation/RootNavigator.tsx`: `Stack.Protected` groups driven only by `getRouteAccess(hasSession)` (`utils/routing.ts`), `(auth)` when signed out and `(app)` when signed in. `app/index.tsx` is the Splash decision (`resolveInitialRoute`: session → home, else onboarding-seen → login, else onboarding); after sign-in/out, screens `router.replace('/')` so Splash re-resolves. `(app)` is a Stack over `(tabs)` (home/learn/review/progress/profile) with `language-selection`, `settings` and `lesson/[id]` on top. Route strings come from `ROUTES`.

**Swappable service seams (mock today, real backend later).** Each has one registration point so screens never import a concrete implementation:
- `services/auth`: `AuthService` (+ `MockAuthService`, `registerAuthService`). `store/authStore.ts` derives session state **only** from `onAuthStateChange`. Request types are a union keyed on `method` for future Google/Apple. The mock persists the session (user + timestamp, never a password) under `STORAGE_KEYS.session`, so restarts restore it. Test hooks: any valid email + 8+ char password signs in; emails starting `fail@` → invalid credentials, `offline@` → network error, `taken@` → email in use (sign-up).
- `services/repositories`: `Repositories` interfaces + `createMockRepositories({ storage, now })` over `src/mocks/*`; `getRepositories()`/`registerRepositories()`. The default instance uses device storage, so finished lessons and study minutes persist per `userId:language` (study minutes reset per calendar day); tests get isolated in-memory storage. `completeLesson` is serialized and saves before publishing state. Screens read data via `hooks/useCurrentLearning`, `useLessonList`, `useAsyncData`.
- `services/ai`: `AIProvider` + `MockAIProvider`, `registerAIProvider`/`getAIProvider`. Nothing beyond the mock.
- `services/speech.ts`: `SpeechService` (`DeviceSpeechService` over `expo-speech`, the device's own TTS; `registerSpeechService`/`getSpeechService`). `components/PronounceButton` speaks a word in its `targetLanguage` (BCP 47 tag from `SPEECH_LANGUAGE_TAGS`), hides itself when the device reports no voice for that language (an empty/failed voice list means "unknown" and keeps it), and stops its word on unmount. Shown in the lesson word list, the quiz prompt (multiple-choice only: a translate option would give the answer away) and the Review card. `hooks/useSpeechSupport` is the shared voice check; `components/ListeningPractice` ("hear it, pick the written word", `buildListeningExercises`, type `listen`) is a practice mode on the lesson screen next to the match game and never plays on its own. `jest.setup.ts` mocks `expo-speech` with a voice list that never settles.
- `services/storage.ts`: the `KeyValueStorage` seam (`deviceStorage` = AsyncStorage, `createMemoryStorage()` for tests).

**Data model** (`src/types`): source and target language are separate concepts; `Language.roles` controls what is selectable (`languages.getSources()`/`getTargets()`; every language has both roles). The learner level lives on `Progress` (per target language); the streak is per user (`Streak`), not per language. Adding a language = an entry in `mocks/languages.ts` plus lessons/vocabulary/progress seeds.

**Lessons (offline).** Ten A1 and ten A2 lessons per language (ids `<lang>-a1-<n>`, `<lang>-a2-<n>`): outlines in `mocks/lessons.ts` (`a1Templates`, `a2Templates`), words in `mocks/vocabulary.ts` (`courses.a1`/`courses.a2`, one list per language) at the same index; `lessons.getByLanguage` orders by level, then position; Learn groups lessons under a header per level and Home's "Lesson x of n" counts within the level. A2 content has not been reviewed by a linguist yet. Exercises are generated deterministically from the vocabulary (`utils/exercises.ts`: distractors and answer position come from a generator seeded by the exercise id, never `Math.random`). Pure rules: `utils/progression.ts` (a run completes its lesson only at `PASS_RATIO` = 70% correct; a failed run keeps the lesson current but still earns XP without the bonus (`lessonXp`) and minutes; level rises when all lessons of the level are done; XP/study time count on replay, new words don't), `utils/lessonSession.ts` (quiz state machine). After sign-in every account chooses its own (source) language and the language to learn (`(app)/setup-languages`, persisted per user by `repositories.profiles` under `STORAGE_KEYS.learningProfile`); the splash sends accounts without a choice there. `store/learningStore.ts` holds that `profile` and `progressVersion`, which screens use to reload after a lesson. Meanings are shown in the source language (`meaningOf(word, source)`); every word carries meanings in all other course languages. New accounts start with empty progress and a streak of 0; the streak is computed from recorded activity days (`utils/streaks.ts`); a lesson run or a vocabulary review records the day, a practice run (match game, listening) does not. Practice runs are stored as attempts with `kind: 'practice'` (`completeLesson` writes `kind: 'lesson'`; older saves have no kind and count as lesson runs), and the retry-lesson recommendation reads lesson runs only. A passed lesson puts each of its words that has no review state yet on the review schedule (`repositories.reviews`, `STORAGE_KEYS.vocabReviews`, first due one day later via `initialReviewState`); all scheduling lives in `utils/srs.ts`, and the Review tab shows the due words.

**i18n and RTL.**
- `i18n/locales/ar.ts` is the source of truth: it types `Translation` (`i18n/types.ts`) and the i18next key typing (`i18n/i18next.d.ts`). `en.ts` must match; `i18n.test.ts` enforces key parity (ignoring plural suffixes). Arabic plurals need all six suffixes (`_zero…_other`). No literal UI strings in screens; the app name is `t('app.name')` (it appears only in `app.json` and the locale files).
- `services/appLanguage.ts` `applyLanguagePreference` is the single path from the stored preference to i18n **and** native layout direction (startup and Settings both call it). Locale = manual preference, else device language, else Arabic (`i18n/resolveLocale.ts`). A changed direction needs a reload via `reloadApp()` (`reloadAppAsync` from `expo`; `DevSettings.reload` is a no-op outside `__DEV__`). **Expo Go resets runtime RTL overrides**, so manual language switching on a device is unverified (see TESTING.md).
- Use logical style props (`marginStart`, `start/end`), `Icon directional` for arrows, and `utils/bidi.ts` (`isolate`, `isolateLtr`, `isolateNative`) around mixed-script text. Languages are shown with a decorative flag (`LanguageBadge`, `Language.flag`) next to the name, which is what screen readers announce.

**Theme.** Home's header uses the brand hero gradient (`heroStart/heroMid/heroEnd`, same in light and dark, via `expo-linear-gradient`) with `onHero*`/`heroGold` text and a `gold` CTA (`Button variant="gold"`); its parts live in `components/home/`. The other tabs share `ScreenHero` (same gradient header), `HeroProgress`, `StreakChip`, `LessonRow` (Learn path) and `ReviewOutcomeButton` (colour per outcome + the next interval from `utils/srs.ts`); `StatTile` takes `highlight` for the gold headline figure. In-app stack screens (settings, lesson, language choice) use a native header in the hero colour (`(app)/_layout.tsx`) followed by `ScreenHero topInset={false}`; sign-in/up use `BrandHero`; Onboarding is a full brand-gradient screen. `useTheme()` combines the persisted preference with the OS scheme (`theme/resolveScheme.ts`). Palettes are in `theme/colors.ts`; `theme.test.ts` asserts text/background pairs are ≥ 4.5:1, interactive borders (`borderStrong`) ≥ 3:1, and that light/dark define identical tokens, so change colors together with that test. Cairo is used via explicit per-weight font families (`theme/typography.ts`), not `fontWeight`.

**Persistence.** AsyncStorage keys are in `STORAGE_KEYS`: preferences (`store/preferencesStore.ts`, zustand `persist` with `partialize`: theme, UI language, `onboardingSeen`), the mock session, and learning progress. Reads of stored blobs are defensive: corrupt data is treated as "nothing saved".

## Brand, release and website
- **Visual identity** (icon, hero gradient, gold CTA, Cairo) lives in `assets/icon-src/*.svg` (sources) → `assets/images/*.png` and `assets/store/feature-graphic.png` (generated; commit both). Android adaptive icon background/splash colour is `#0A4E49`. iOS uses `assets/images/icon.png` (opaque, no alpha).
- **Android release** (not done yet, needs the owner's accounts): `eas.json` (profiles `preview` APK, `production` AAB, `autoIncrement`), listing text `docs/store/play-listing.md`, `docs/store/data-safety.md`, steps `docs/store/RELEASE_ANDROID.md`. `android.package`/`ios.bundleIdentifier` = `com.lughati.app`; it is **permanent after the first Play upload**. Keep Data-safety/privacy answers in sync with reality: the app makes no network calls and stores everything on the device (adding a backend or analytics requires updating them first). Pronunciation hands lesson words to the system TTS engine only; the policy says so.
- **Website** `site/` (static, ar at `/`, en at `/en/`, privacy at `/privacy`) is generated, do not hand-edit the HTML: change `scripts/build-site.py` (copy, features, mockups) or `docs/store/privacy-policy.md`, rebuild and commit. Contact e-mail: `CONTACT_EMAIL` in `build-site.py` and the policy markdown (keep both in sync). Cairo is self-hosted, no third-party requests or cookies; mockups are labelled as illustrations (do not present them as store screenshots) and the Play button says "coming soon" until the app is published.
- **Hosting:** Vercel project `lughati` (team `mot1209's projects`), connected to `MOT1209/Lughati`, root directory `site`, no build step, Vercel Auth disabled so the pages are public. `main` deploys to production automatically; the public URL is `https://lughati-sigma.vercel.app`.

## Git
This folder is its own git repo (remote `origin` → `https://github.com/MOT1209/Lughati.git`, branch `main`) nested inside a larger monorepo whose root is two levels up with unrelated remotes; run git from this directory and never push the parent repo here. `origin/main` also receives pull-request merges from other sessions (`claude/*`, `fix/*` branches), so `git fetch` and merge/rebase before pushing, and never force-push. Merge to `main` (via a PR) only when the owner asks; commits end with the attribution lines the session specifies. Run typecheck + lint + the full jest suite before every push (the suite takes ~10 s locally).
